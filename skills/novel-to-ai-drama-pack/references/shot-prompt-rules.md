## 核心语法

把每个素材令牌紧跟它所属对象的名称：

```text
名称@reference_token
```

名称和 `@` 之间不得有空格、换行、冒号或括号。不把令牌单独放在句首，不建“引用清单”代替句内引用。

基本格式：

```text
林岚@角色_C001_林岚_综合设定图_V001推门进入酒楼包厢@场景_S001_酒楼包厢_场景设定图_V001。
```

`reference_token` 必须与 `project.json.assets[].reference_token` 中当前活动资产的值字符级完全相同，不带 `.png`、`.jpg` 或其他扩展名，不使用简写、别名或模糊版本。提示词预检阶段允许活动资产尚待生成；实际附图和正式导出时才要求它已完成。

## 令牌边界

注册令牌以精确 `_VNNN` 结束。本 Skill 使用无分隔符的中文句内语法，因此允许在令牌后立即继续中文叙事：

```text
@角色_C001_林岚_综合设定图_V001推门进入
```

扫描器将已注册的 `_V001` 视为令牌结尾，将后续中文字视为叙事。这是用户指定的无分隔句内语法，不要为了“隔开令牌”而添加空格。

如果在 `_VNNN` 后立即追加 ASCII 字母、数字、下划线或连字符，扫描器将其视为伪造令牌的延伸并拒绝：

```text
@角色_C001_林岚_综合设定图_V001_fake   # 错
@角色_C001_林岚_综合设定图_V0012       # 错
```

任何以 `@` 开始但不能完全解析到注册表的连续字符串都是未知令牌。不在自由叙事中把 `@` 用作普通标点。

## 必需引用

对每个镜头，根据结构字段建立必需令牌集：

- `character_ids` 中每个人物必须以自己的正式 `name@character_sheet` 出现一次。
- `scene_id` 对应场景必须以 `name@scene_sheet` 出现一次。
- `prop_ids` 中每个道具必须以 `name@prop_sheet` 出现一次。
- `food_ids` 中每个菜肴必须以 `name@food_image` 出现一次。

`script_episode_count` 范围内每个 `character_ids` 人物（包括 `minor`）都必须有基础 `character_sheet`，每个 `scene_id` 场景（包括 `secondary`）都必须有 `scene_sheet`。只要对象在指定集数的提示词出现，就不能以“不是第一集”或“重要性较低”为由省略基础图。

普通小物件只写自然语言，不写入 `prop_ids`，不创建图片资产，不写 `@`。重要物品、武器、信物、证物、车辆、设备和命名菜肴在列入对应 ID 数组后必须有图且在句内引用。

不添加与镜头无关的注册令牌。每个必需令牌只消费一次；同一令牌的脱离、重复或不相关出现都是错误。

## 表情与动作链

`expression_asset_id` 或 `action_asset_id` 为非空时，将对应令牌紧接在同一角色的基础角色令牌后，中间不插入空格、叙事或标点：

```text
林岚@角色_C001_林岚_综合设定图_V001@角色_C001_林岚_表情设定图_V001@角色_C001_林岚_动作设定图_V001拔剑。
```

链的第一项永远是当前集的活动 `character_sheet`。表情/动作图必须：

- 是 `completed`。
- 属于本镜头 `character_ids` 中的角色。
- 其父角色图与本集活动角色图相同。
- 在中英文提示词中使用完全相同的链。

当前镜头字段各只能选一个表情资产 ID 和一个动作资产 ID。不用没有字段承载的自创多人表情链扩展当前 canonical 契约。

不为 `minor` 或 `cameo` 在镜头中选择 `expression_asset_id` 或 `action_asset_id`，因为当前媒体工作流不保证为它们生成附加图。如果剧情确实需要，先有意识地将角色升级为 `major`，或在 canonical 资产库中显式注册并完成与当前角色阶段匹配的表情/动作资产，然后再选择。

## 活动版本选择

为镜头选择引用时：

1. 只从 `assets` 注册表中选择，不从目录文件名猜测。
2. 忽略 `discarded`，并对逻辑资产的同一阶段取最高版本。
3. 如果存在覆盖当前 `episode_number` 的 `episode_range`，选该范围版本；否则选无范围的全局版本。
4. 把选中的最高 `non-discarded` 版本视为活动版本。它可以是 `redo`、`confirmed` 或 `generating`；提示词使用该活动版本的预注册令牌，媒体工作单通过依赖确保在子资产前生成它。不得回退引用同阶段的旧 `completed` 版本。
5. 对重叠范围、多个全局候选或父资产歧义立即停止，不随机选择。

只在实际调用图片生成器附上参考图或进入正式导出时，才要求活动资产已有真实文件且为 `completed`。对尚待生成的活动版本，先建任务和提示词，再按拓扑顺序完成媒体。

重做资产必须使用新 `_VNNN` 令牌。当新版本成为活动版本后，更新受影响的提示词与示范图父资产，不改写已完成资产的历史记录。

## 中英文一致

`prompt_zh` 和 `prompt_en` 必须包含完全相同的令牌集，每个令牌字符级相同，不翻译令牌、不替换中文文件名。

英文提示词也保留对象的正式中文 `name`，让令牌仍能紧跟名称：

```text
林岚@角色_C001_林岚_综合设定图_V001 enters 酒楼包厢@场景_S001_酒楼包厢_场景设定图_V001 from frame right.
```

中英文可以使用不同叙事语法，但角色、场景、道具、菜肴、版本和附加表情/动作不得有任何差异。

## 镜头提示词结构

使用以下顺序写每个镜头，只保留本镜头可见可听的信息：

1. 画幅、时代、时间、天气、光线和场景 `name@token`。
2. 景别、摄影机高度、角度、焦段感、景深和构图。
3. 每个出镜人物的 `name@token`、初始位置、身体朝向、视线和初始表情。
4. 人物的分步动作、手部动作、与他人/物品的接触，以及重要道具/菜肴 `name@token`。
5. 摄影机从什么状态开始，何时以什么速度运动，如何响应人物。
6. 背景中有原因的环境动态，如风、雨、火光、行人、帘幔或烟尘。
7. 角色的结束位置、结束表情和镜头最终停留点。
8. 与下一镜头的动作、视线、构图、声音或光线衔接。

视频提示词可以被复制给外部视频模型，但本 Skill 不调用视频生成器，不产出视频文件。

## 动作与运镜

将动作写成有顺序、方向、速度和终点的可见变化：

```text
林岚从画面右后方进入，左手扶门，先看向桌面，再将视线移向画面左侧的长剑；她的表情由警觉转为震惊。
```

将运镜写成摄影机的空间行为：

```text
摄影机位于房间左前方腰部高度，随她入内缓慢后移，当她看见长剑时停止并缓慢推近，最后停在她眼睛近景。
```

避免“男主走进房间”、“镜头很有电影感”等不可执行句子。一个 2–8 秒镜头不承载多个复杂技击、多人换位、变身、爆炸和长对白；拆分为准备、发生和结果镜头。

## 景别与构图

根据信息目标选景别：

- 全景/远景：建立空间、角色数量、危险方向或规模。
- 中景：展示对话关系、手持物和身体动作。
- 近景：展示表情变化和人物反应。
- 特写：展示眼睛、手、重要道具、菜肴细节或线索，并交代它与前后镜头的空间关系。

为 9:16 竖屏把关键脸、手和物品放在安全区内，预留必要字幕区，但不因竖屏而把多人挤成平面队列。用前景、中景和背景保持空间层次，清楚标记人物左右和前后位置。

## 连续性

写新镜头前读取前一镜头与 canonical 时间线，锁定：

- 人物活动阶段、服装、发型、伤势、表情余波、站位和进出方向。
- 道具持有人、左右手、完整/损坏状态、放置位置和相对比例。
- 场景门窗、家具、道路、光源、时间、天气和破坏状态。
- 上一镜头的景别、视线、轴线和动势，避免无意跳轴、瞬移或手持物换边。

在 `shot_sample` 生成后再用图像检查验证这些锁定。提示词通过不代表图片已经通过连续性。

## 负面提示词

根据镜头风险写可验证的禁止项：

- 人物：换脸、五官/年龄/发型/服装变化、多余人物、多余肢体、手指错误、穿模、嘴型异常。
- 物品：武器变形、道具消失、器皿或摆盘改变、持有人错误。
- 场景：结构变化、家具移位、光源方向突变、背景闪烁。
- 运动：人物瞬移、动作跳变、镜头乱抖、无原因缩放或变焦。
- 画质：低清、过曝、过度锐化、乱码、字幕、标志、水印。

不把“低质量、不好看”当作唯一负面词；将它拆成能被检查的具体失败。

## 正反例

### 人物与场景

正确：

```text
林岚@角色_C001_林岚_综合设定图_V001从画面右侧推门进入酒楼包厢@场景_S001_酒楼包厢_场景设定图_V001。
```

错误——令牌脱离名称：

```text
@角色_C001_林岚_综合设定图_V001 林岚推门进入。
```

错误——名称与 `@` 有空格：

```text
林岚 @角色_C001_林岚_综合设定图_V001推门进入。
```

### 人物、重要道具与菜肴

正确：

```text
林岚@角色_C001_林岚_综合设定图_V001坐在酒楼包厢@场景_S001_酒楼包厢_场景设定图_V001内，她把青铜长剑@道具_P001_青铜长剑_道具设定图_V001放在莲花酥@食物_F001_莲花酥_食物设定图_V001旁。
```

普通小物件正确写法：

```text
她拿起桌边的普通茶杯，杯子无图片资产，不写 @。
```

错误——分离引用表：

```text
引用：@角色_C001_林岚_综合设定图_V001 @场景_S001_酒楼包厢_场景设定图_V001
画面：林岚走进酒楼包厢。
```

### 中英文

正确：

```text
ZH: 林岚@角色_C001_林岚_综合设定图_V001站在酒楼包厢@场景_S001_酒楼包厢_场景设定图_V001。
EN: 林岚@角色_C001_林岚_综合设定图_V001 stands in 酒楼包厢@场景_S001_酒楼包厢_场景设定图_V001.
```

错误——英文中翻译或遗漏令牌：

```text
EN: Lin Lan@character_C001_LinLan_sheet_V001 stands in the room.
```

## 生成前校验

完成每批镜头后运行：

```bash
python3 "$SKILL_DIR/scripts/validate_project.py" PROJECT/project.json
python3 "$SKILL_DIR/scripts/build_media_jobs.py" PROJECT/project.json
```

`build_media_jobs.py` 会检查 `script_episode_count` 范围内每一集的句内令牌，并将待生成的活动资产放入依赖图，因此可以在它们尚未 `completed` 时预检；该校验范围不会把 E002 及之后的剧集扩大成镜头图或对白任务。当指定集数的提示词引用的基础图都已生成并登记后，再运行：

```bash
python3 "$SKILL_DIR/scripts/validate_references.py" PROJECT/project.json
```

然后确认：

1. 所有对象 ID 已存在，每个所需图片都选中当前集的唯一活动版本；待生成版本已建依赖任务，实际附图和正式导出前已完成。
2. 每个名称紧跟精确令牌，没有空格、错版、脱离、重复、无关或未知令牌。
3. 中英文令牌集完全相同。
4. 普通小物件没有误入引用链，重要物品和菜肴没有遗漏。
5. E001 每个镜头只建一个示范图任务，E002/E003 没有示范图任务。

任何校验错误都要在向图片生成器传入参考图前解决。
