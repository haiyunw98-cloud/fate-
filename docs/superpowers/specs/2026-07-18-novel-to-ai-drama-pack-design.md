# 小说转 AI 短剧素材包 Skill 设计

## 1. 目标

创建一个可在 Codex 本地运行的 `novel-to-ai-drama-pack` Skill。用户上传完整小说后，Skill 通读全文，建立统一资产数据库，输出全剧改编规划、前三集剧本与详细分镜提示词，并实际生成核心人物、场景、重要物品、菜肴和声音资产。

第一版用于验证真实生产流程，为后续可视化平台提供稳定的数据结构和工作流。第一版不生成视频文件。

## 2. 第一版范围

### 2.1 输入

- TXT、DOCX、文本型 PDF、Markdown、EPUB 或粘贴文本。
- 原始文件只复制和读取，不移动、不覆盖、不改写。
- 长篇小说必须通读全文；内容过长时分批处理，但先建立全局故事圣经和完整集纲。

### 2.2 文本输出

- 小说解析、世界观、时间线、伏笔与回收。
- 人物关系、人物弧和人物阶段变化。
- 场景、重要物品、菜肴和声音资产清单。
- 全剧分季、分集规划及原著章节对应表。
- 前三集完整剧本。
- 前三集详细分镜表。
- 每个镜头的中文、英文和负面视频提示词。
- 配音表、声音表、音乐与音效建议、剪辑执行表。

### 2.3 实际生成的媒体

- 每名重要角色生成一张综合角色设定图。
- 主角和主要配角各生成一张表情设定图和一张动作设定图。
- 每个重要场景生成一张场景综合设定图。
- 重要剧情物品、武器、车辆和设备生成综合设定图。
- 重要菜肴、特色食物和宴席生成菜肴图。
- 第一集每个镜头生成一张示范画面，用于验证人物、场景和画风一致性；不生成首帧、关键动作帧、尾帧三套图片。
- 主角和主要配角各生成一段约 20 秒的 AI 声音样本。
- 第一集生成完整角色台词音频。

### 2.4 第一版不做

- 不生成视频文件。
- 不批量生成第二集及之后的分镜图片。
- 不为普通杯子、手机、钥匙、书本等生活小物件生成图片。
- 不进行真人声音克隆。
- 不做账号、支付、团队协作、云端队列和在线平台界面。

## 3. 推荐实现方式

新建通用 Skill，不直接修改现有 `novel-to-seedance-pack`。复用其小说提取、单一事实源、分批续作、确定性校验、局部重做和导出思路，并把数据结构扩展到图片、菜肴和声音生产。

Skill 的版本控制源码放在：

```text
/Users/why/Documents/小说转ai视频/skills/novel-to-ai-drama-pack/
```

验证通过后安装到 Codex 的用户 Skill 目录。后续平台仍以同一数据契约为核心，不重新建立项目数据。

## 4. 总体流程

```text
接收小说
→ 提取全文并建立章节索引
→ 通读全文并建立故事圣经
→ 建立人物、场景、物品、菜肴和声音数据库
→ 完成全剧分季与分集规划
→ 确定统一视觉风格
→ 生成核心资产图片和角色声音样本
→ 生成前三集剧本与分镜提示词
→ 生成第一集示范画面和完整台词音频
→ 执行结构、引用和连续性校验
→ 导出完整素材包
```

媒体生成顺序固定为：

```text
风格参考图
→ 角色综合设定图
→ 角色表情图和动作图
→ 场景综合设定图
→ 重要物品图和菜肴图
→ 第一集镜头示范画面
```

后续资产必须引用前一步已经确认的资产，不允许跳过基础资产直接生成剧情画面。

## 5. 编号与版本规则

### 5.1 对象编号

```text
项目：PRJ001
人物：C001、C002
场景：S001、S002
重要物品：P001、P002
菜肴：F001、F002
服装：W001、W002
剧集：E001、E002
镜头：E001_SH001
声音：AUD_C001、AUD_C002
```

编号创建后永久锁定。改名不改变编号，废弃编号不重复分配。

### 5.2 文件版本

```text
角色_C001_林岚_综合设定图_V001.png
角色_C001_林岚_表情设定图_V001.png
场景_S001_公寓玄关_综合设定图_V001.png
道具_P001_青铜长剑_综合设定图_V001.png
菜肴_F001_莲花酥_标准图_V001.png
声音_AUD_C001_林岚_标准声音_V001.wav
第01集_E001_SH001_示范画面_V001.png
```

重新生成只增加版本号，不覆盖旧文件。所有生成任务记录实际使用的资产版本。

## 6. 分镜提示词中的 `@` 引用

`@` 引用必须紧跟对应的人物名或场景名，不能只放在提示词开头或独立引用清单中。

标准格式：

```text
林岚@角色_C001_林岚_综合设定图_V001推门进入公寓玄关@场景_S001_公寓玄关_综合设定图_V001。
```

规则：

- 人物出场时必须写 `人物名@对应角色综合设定图完整素材引用名`。
- 场景出现时必须写 `场景名@对应场景图完整素材引用名`。
- 表情特写可追加 `@角色表情设定图`。
- 明显动作可追加 `@角色动作设定图`。
- 特殊年龄或换装阶段必须引用该阶段的综合设定图，不引用已经失效的旧造型。
- 多人物镜头必须分别引用每一个人物的角色图。
- 重要物品和菜肴有图片时，在名称后紧跟对应 `@` 图片。
- 普通小物品不生成图片，直接用文字描述，不写 `@`。
- `@` 后使用注册的完整素材引用名，不带 `.png` 等扩展名；注册表再映射到具体版本文件。
- 中文和英文提示词保留完全相同的 `@` 素材引用名。
- 应引用而缺少 `@`、引用不存在文件或使用错误版本时，任务不得进入生成状态。

完整示例：

```text
林岚@角色_C001_林岚_综合设定图_V001坐在酒楼包厢@场景_S008_酒楼包厢_综合设定图_V001内，桌上摆着莲花酥@菜肴_F001_莲花酥_标准图_V001。她先看向画面左侧，随后缓慢起身。摄影机以腰部高度缓慢推进，镜头最终停在她警觉的面部近景。
```

## 7. 单一事实源

每个项目使用一个 `project.json` 作为唯一事实源。Markdown、Excel、提示词文本、图片目录和声音目录都是其派生物，不得反向覆盖 canonical 数据。

核心对象包括：

- `project`：项目标题、规格、阶段和生成范围。
- `source`：来源文件、哈希、章节索引和覆盖范围。
- `analysis`：世界观、主线、时间线、伏笔、完整集纲。
- `characters`：人物档案、阶段、视觉锁、声音锁和关系。
- `scenes`：空间结构、机位、时间、天气和状态。
- `props`：仅收录需要长期一致的重要物品。
- `foods`：重要菜肴、食物和宴席。
- `episodes`：分集规划、剧本和镜头。
- `assets`：所有图片和音频版本、路径、校验值及状态。
- `generation_runs`：生成时间、输入引用、结果、失败原因和重做记录。

每项媒体资产至少记录：

```text
asset_id
owner_id
asset_type
version
file_name
absolute_path
reference_token
status
checksum
generation_prompt
parent_asset_ids
```

状态使用 `draft → confirmed → generating → completed`；失败进入 `redo`，明确废弃才进入 `discarded`。

## 8. Skill 组件

```text
novel-to-ai-drama-pack/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── output-contract.md
│   ├── adaptation-rules.md
│   ├── image-prompt-rules.md
│   ├── shot-prompt-rules.md
│   └── voice-rules.md
├── scripts/
│   ├── extract_source.py
│   ├── validate_project.py
│   ├── validate_references.py
│   ├── export_package.py
│   └── workflow_guard.py
└── assets/
    └── project-template.json
```

职责边界：

- `SKILL.md` 只保存核心工作流、门禁和资源路由，保持精简。
- `references/` 保存详细数据契约和提示词规则。
- `scripts/` 只处理确定性任务，不假装理解剧情语义。
- Codex 负责全文理解、改编、语义连续性审阅和媒体生成决策。
- 图片通过可用的图片生成能力实际创建。
- 声音通过可用的 TTS 能力生成；使用内置 AI 声线和角色表演指令，不克隆真人声音。

## 10. 确认节点

不逐张图片询问用户，只保留集中确认：

1. 小说解析完成后，集中确认改编方向、主要资产清单和视觉风格。
2. 核心人物、核心场景和声音样本生成后，集中确认一致性。
3. 第一集示范素材完成后，确认是否继续后续集数。

用户明确要求自动继续时，Skill 可跳过前两次暂停，但必须保存推断和版本记录。

## 11. 错误处理与恢复

- 扫描 PDF 无正文时停止解析并报告需要 OCR，不猜测正文。
- 输入损坏、加密或为空时保留原文件并明确归因。
- 长篇按有界批次写入，每批原子更新 `project.json`，支持从第一未完成批次恢复。
- 图片或声音生成失败时记录真实错误和失败任务，不伪造文件或完成状态。
- 声音生成缺少本地 API 凭据时，继续输出声音档案与待生成任务，但明确标记媒体交付未完成。
- `@` 引用不存在、版本错误或对象类型不匹配时阻止该任务生成。
- 重做只修改选定资产或镜头，保留旧版本和完整审计记录。
- 未通过正式校验时不得报告完整素材包已经完成。

## 12. 校验与测试

### 12.1 确定性校验

- JSON 结构、必填字段、枚举和编号唯一性。
- 文件名、对象编号和版本号一致。
- 所有 `@` 引用能够解析到已存在且状态可用的图片。
- 分镜中出现的重要人物和场景均有正确的句内 `@` 引用。
- 普通小物品不会错误触发图片资产要求。
- 重要物品和菜肴能够正确引用各自资产类型。
- 相邻镜头和相邻剧集的服装、伤势、天气、道具归属和人物位置连续。
- 导出文件全部由同一 `project.json` 派生。

### 12.2 测试层级

- 单元测试：正文提取、编号、版本递增、文件命名、`@` 引用解析和导出。
- 契约测试：合法项目通过；缺失引用、错误版本、重复编号和悬空资产必须失败。
- 集成测试：使用一篇短篇小说跑通解析、资产登记、图片任务、声音任务和第一集导出。
- 媒体抽检：检查人物五官、服装、场景结构、菜肴外观和声音可懂度。
- 恢复测试：在中断的项目上继续，已确认资产不得被重写。

## 13. 完成标准

第一版 Skill 只有同时满足以下条件才算完成：

- Skill 目录通过基础格式验证。
- 输入提取、项目校验、引用校验和导出脚本测试通过。
- 使用真实或代表性小说完成一次端到端试运行。
- 核心资产图片实际存在并登记版本。
- 主角和主要配角声音样本实际存在；若外部凭据缺失，必须明确报告为未完成而非成功。
- 第一集示范画面和台词音频按获准范围完成。
- 前三集剧本、分镜提示词和全部 `@` 引用通过校验。
- 导出包能从 `project.json` 重建，且没有悬空引用。
